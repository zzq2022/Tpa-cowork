# TPA CoWork 全量品牌硬切换设计

## 1. 目标

将产品从 Hope Agent 全量迁移为 TPA CoWork。运行代码、安装产物、用户界面、数据目录、命令行、服务、浏览器扩展、生成文件和协议身份均不再使用旧品牌，也不提供旧品牌兼容入口。

本设计落实 `BRAND-001`，并明确采用分阶段硬切换，避免无差别全仓替换造成路径、协议或打包回归。

## 2. 已确认决策

- 产品显示名统一为 `TPA CoWork`。
- 默认 Agent 名统一为 `TPA-Agent`。
- 主数据目录为 `~/.tpa-cowork/`。
- 二进制和系统服务名为 `tpa-cowork`。
- 环境变量前缀为 `TPA_COWORK_`。
- 不读取、迁移或删除 `~/.hope-agent/`。
- 不识别 `HA_*` 或 `HOPE_*` 环境变量。
- 不保留旧二进制、服务、Native Host 或其他旧身份别名。
- 旧数据不会自动出现在新版中；需要旧数据的用户必须在切换前自行导出。
- 许可证、第三方来源和必要的上游归属说明可以出现旧名称，但必须进入精确白名单并记录理由。

## 3. 命名规范

| 语义 | 新值 |
|---|---|
| 产品显示名 | `TPA CoWork` |
| 标题式机器标识 | `TPA-CoWork` |
| 无分隔符标识 | `TPACoWork` |
| 文件、包、二进制和服务标识 | `tpa-cowork` |
| 数据目录 | `.tpa-cowork` |
| 环境变量前缀 | `TPA_COWORK_` |
| 默认 Agent 名 | `TPA-Agent` |
| HTTP User-Agent | `TPA-CoWork/<version>` |
| Office 作者、修订者和应用元数据 | `TPA CoWork` |

具体标识受平台格式限制时，从上表选择合法形式，不自行创造第四种拼写。

## 4. 架构

### 4.1 单一产品身份来源

新增 `tpa/product.toml` 作为产品身份真相源，至少定义显示名、slug、紧凑名、默认 Agent 名、数据目录名、环境变量前缀、二进制名、服务名、User-Agent 产品段和 Native Host ID。

Rust 通过 `crates/tpa-product/` 暴露强类型常量和路径入口；前端通过 `src/tpa/product.ts` 使用生成或校验后的常量；打包、安装和检查脚本读取 `tpa/product.toml`。业务代码不得新增品牌字面量。

产品定义的生成或同步过程必须可重复执行，并提供 check 模式供本地门禁与 CI 使用。生成文件必须带来源注释，禁止手工修改。

### 4.2 展示层

以下入口全部使用产品身份来源或对应 i18n 文案：

- React 窗口、About、设置、聊天、通知、终端、更新历史和引导页；
- Tauri 窗口、菜单、托盘、退出确认和系统权限说明；
- CLI、Server banner、fallback 页面、OAuth 页面和错误信息；
- 内置技能、工具描述、模型可见提示和帮助内容；
- Office 文档作者、修订者、应用元数据；
- 浏览器扩展、Native Host、安装器和系统包信息。

i18n 只维护项目允许的 `zh`、`zh-TW`、`en`。fallback 文案也必须使用新品牌，不能因翻译 key 缺失重新暴露旧名称。

### 4.3 运行身份层

运行时只接受新身份：

- 路径统一经 `paths` 公共入口解析到 `~/.tpa-cowork/`；
- 配置、凭据、数据库、日志、缓存、更新 staging、工作树和临时持久化目录都位于新根目录；
- 所有环境变量改为 `TPA_COWORK_*`；
- CLI、后台服务、进程探测、安装/卸载、重启和更新器只识别 `tpa-cowork`；
- Native Host 使用新的 TPA CoWork ID 与清单；
- HTTP、知识导入、Issue 上报等网络身份使用新的 User-Agent；
- 终端 `TERM_PROGRAM`、日志标签和诊断输出使用新身份。

新身份初始化失败时明确报错，不回退旧路径、旧变量、旧服务或旧 Host。应用不得主动删除旧目录。

### 4.4 旧兼容层删除

删除旧目录迁移器、迁移 sentinel、旧环境变量 fallback、旧服务/进程发现、旧 Native Host 注册与探测、旧二进制别名，以及只为这些路径存在的测试和文档。

数据结构、数据库 schema 和安全逻辑不因品牌切换而重写。只有字段值或路径确实构成产品身份时才改名，避免把普通的 `agent` 领域术语误改为品牌。

## 5. 分阶段实施

### 阶段一：身份基础设施

建立 `product.toml`、Rust/TypeScript 消费层、同步检查和旧品牌白名单。先为产品常量、生成一致性和扫描规则建立失败测试，再迁移调用方。

### 阶段二：用户可见品牌

按 React、Tauri、Server/CLI、OAuth、技能/工具、Office 和扩展/安装器分组迁移。每组独立完成测试、验证和审查，不执行全仓无差别替换。

### 阶段三：内部身份硬切换

迁移数据根目录、环境变量、二进制、服务、Native Host、网络身份、终端身份、安装器和更新器。验证旧目录存在或只设置旧变量时应用仍完全忽略它们。

### 阶段四：兼容代码清除

删除所有旧身份兼容分支和测试，更新架构、用户指南、发布与维护文档。保留的上游归属文字进入审计白名单。

### 阶段五：产物验收

验证 GUI、CLI、Server、安装包、扩展、Office 生成物和新数据目录，并对源码与解包产物执行旧品牌扫描。

## 6. 品牌审计

新增确定性检查脚本，扫描至少以下模式：

- `Hope Agent`
- `Hope-Agent`
- `HopeAgent`
- `hope-agent`
- `.hope-agent`
- `HA_`
- `HOPE_`

白名单必须精确到文件和用途，允许范围仅限许可证、第三方来源、上游归属及不可更改的外部引用。注释、测试夹具和历史文档不会因为“用户不可见”而默认放行。

脚本同时提供源码扫描和产物目录扫描模式。新增旧品牌残留时检查失败，并输出文件、行号和命中模式。

## 7. 错误处理与数据策略

- 新数据根目录不可创建或不可写：启动失败并显示新路径。
- 新服务未安装：报告 `tpa-cowork` 服务未安装，不探测旧服务。
- 新 Native Host 不存在：提示安装 TPA CoWork Host，不连接旧 Host。
- 只存在旧目录：按首次启动处理，不读取、不移动、不删除旧数据。
- 只存在旧环境变量：视为未配置，不发出兼容 fallback。
- 打包或生成的身份配置不一致：构建检查失败，不在运行时猜测。

## 8. 测试与验收矩阵

### 8.1 静态与单元验证

- 产品定义的 Rust 与 TypeScript 值一致；
- 品牌同步 check 通过；
- 旧品牌扫描除白名单外零命中；
- React 相关测试与 `pnpm typecheck` 通过；
- 涉及的 Rust crate 执行单点 `cargo check -p <crate>`；
- `node scripts/sync-i18n.mjs --check` 通过。

### 8.2 运行入口

- Tauri 主窗口、Help、About、菜单、托盘、通知和退出确认只显示 TPA CoWork；
- CLI help、启动、错误和诊断输出只显示 TPA CoWork；
- HTTP Server banner、fallback 页面、OAuth 页面和响应身份只显示 TPA CoWork；
- Office DOCX/XLSX/PPTX 的作者、修订者与 Application 元数据为 TPA CoWork；
- 浏览器扩展与 Native Host 使用新名称和新 ID。

### 8.3 硬切换场景

- 干净环境首次启动只创建 `~/.tpa-cowork/`；
- 同时存在新旧目录时只读取新目录；
- 仅存在旧目录时创建全新的新目录；
- 仅设置旧环境变量时旧变量无效；
- 旧服务、旧二进制或旧 Host 存在时不被发现或调用；
- 更新、重启和卸载流程只操作新身份。

### 8.4 发布产物

- Windows、macOS 和 Linux 安装信息一致；
- 解包后的桌面产物、Server 产物、扩展和安装脚本通过旧品牌扫描；
- 运行时创建的日志、诊断包和生成文档不包含旧品牌。

## 9. 风险与控制

- **旧数据不可见**：这是已确认的硬切换行为；发布说明必须在升级前明确导出要求。
- **环境变量破坏性变更**：提供新变量映射表，但代码不读取旧变量。
- **服务和更新链断裂**：安装、更新、重启、卸载作为一个原子主题迁移和验收。
- **Native Host 失联**：扩展清单、Host 清单和注册脚本在同一阶段修改。
- **上游升级重新带回旧品牌**：品牌审计进入本地门禁与 CI，白名单保持最小化。
- **误改协议或普通领域术语**：禁止盲目全仓替换；每组变更使用精确文件清单和测试。

## 10. 非目标

- 不迁移旧用户数据；
- 不提供旧环境变量、服务、二进制或 Host 的兼容期；
- 不重写与品牌无关的业务架构；
- 不修改第三方项目自身的合法名称；
- 不在本次工作中处理与品牌迁移无关的历史技术债。

## 11. 完成标准

当且仅当以下条件全部满足时迁移完成：

1. 所有运行入口和发布产物只使用 TPA CoWork 身份；
2. 新版只使用新数据目录、环境变量、服务、二进制和 Native Host；
3. 旧身份兼容代码已删除；
4. 源码与产物审计除批准白名单外零命中；
5. 三种运行模式及各平台打包入口完成验证；
6. 破坏性升级说明明确告知旧数据和旧配置不会自动迁移。
